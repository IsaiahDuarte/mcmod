# P1 portable scheduler/accounting baseline — 2026-10-03

This is a local portable-core baseline, not a Minecraft server, client-network,
Wasm or full-release performance result. D07/A15 remain partial.

## Environment and reproduction

Apple M1, eight logical processors; macOS 15.3.1 arm64; Homebrew OpenJDK 21.0.12;
standalone benchmark JVM maximum heap 2,147,483,648 bytes. CPU/OS were also
reported by the harness. Physical RAM: 8,589,934,592 bytes (8 GiB), model MacBookPro17,1, directly
reported by `sysctl -n hw.memsize hw.model machdep.cpu.brand_string`.
The uncommitted measured scheduler/harness changes build on `08c5786` and are
committed with this evidence. Compiler/static/test gates passed before measurement.
No other game/server workload is included in this portable run; other desktop
processes and garbage collection were not controlled, so outliers are retained.

Command: `./gradlew spotlessApply build coreBenchmark`.
Three warmup passes then five measured passes per small/large/overload/idle
scenario; 2,000 ticks per pass, 40,000 recorded ticks total. The harness times
admission plus execution. Thread allocations exclude later CSV formatting.
Workload parameters and numerical targets were selected in
[ADR 0003](../decisions/0003-scheduling-workloads.md) before the final instrumented
baseline. Additional latency/allocation/client-network targets fill the initially
missing measures; no existing timing target was moved. Two exploratory runs
preceded the final run; the first exposed stock depletion in the harness and is
excluded. The final workload keeps transfers active based on current stock.

[Raw gzip CSV](core-v1-2026-10-03.csv.gz) is the exact final harness output,
compressed with gzip mtime zero. SHA-256:
`7e7dad297ad900e0ee4999adf36af4721f9c4d9363da541c7a6c50ce2087041c`.
To inspect, Python's standard-library `gzip.open` and `csv.DictReader` suffice;
rerunning the harness writes `build/benchmarks/core-v1.csv`.

## Target assessment and limits

The p99 <= 10 ms, queue latency, allocation and queue bounds held in these
scenarios. **Timing targets were not universally met:** 2/10,000 small ticks
exceeded 2 ms; 5/10,000 large and 2/10,000 overload ticks exceeded 5 ms. Large
mean throughput was 4095.5136 versus the selected 4096 units/tick target because
the elapsed-time budget deferred work during outliers. Do not relabel these as
full passes or raise the targets. Small and overload mean-throughput targets held.

Peak observed Java heap use was 144,623,496 bytes across the run. This includes
harness data and garbage; it does not prove retained mod state below 512 MiB,
native/RSS use or full-game allocations. Packet limits, actual Minecraft tick
cost, crafting/UI/Wasm workload, multiplayer behavior and Linux/Windows execution
are still unmeasured. D07 baseline establishment is progress, not A15 completion.
