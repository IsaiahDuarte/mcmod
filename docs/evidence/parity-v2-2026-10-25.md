Scope: [parity plan](../PARITY_PLAN.md) slice V2 (re-take the terminal, crafting, filter and
drive screens and repeat the comparison). Minecraft 1.21.1, NeoForge 21.1.252, OpenJDK
21.0.13, Linux x86_64 (Wayland), framebuffer 1708×960 unless a file says otherwise.

Screenshots in [parity-v2-2026-10-25/](parity-v2-2026-10-25/) come from the presentation tour
(`runPresentationClient`), the isolated JEI client (`runJeiClient`) and the two-client check
(`runMultiplayerCheck`) on this date. `presentation.txt` is that run's report.
`SHA256SUMS` covers every file. Commit IDs are in each slice's evidence line in the plan.

This is a comparison with AE2, RS and SFM made by reading their documented, everyday
features. It is not a human playtest; V1 (A17) is still open.

## Everyday loop, side by side

| Everyday expectation | AE2 / RS | Factory Core now |
| --- | --- | --- |
| Read stock at a glance | Corner counts, sort and search | Corner counts; name/qty/mod sort in both directions; @mod and #tag search |
| Ask for something to be crafted | Typed amount, full plan, monitor | Typed amount, full plan with shortages and loops, per-step monitor, finish toast |
| Find what can be crafted | Craftables in the grid | ⚒ toggle with + rows; middle-click or JEI Ctrl-click opens the request |
| Route items into specific storage | Storage-bus filter, cell partition, priority | Storage-mode insert filter, cell partition, drive and Interface priority |
| Edit a filter | Ghost slots, JEI drag, fuzzy toggle | Ghost slots, JEI drag, Item / Exact / Tag per slot |

Differences kept on purpose (SPEC R11 and the plan's "Not in scope"): no channels or cable
counts, no voiding, no implicit chunk loading. Only one difference is new from Wave B. A
terminal deposit makes one transfer per request, so a partial fill leaves the rest with the
player rather than spilling across several containers. ADR 0013 records this.

## Issues found and fixed during the waves

- The two-client multiplayer check had been stale since U3 removed the Take 1 button. It
  now uses the grid's withdraw payload and retries a stale-revision drop (P3).
- A new Jobs button reused the `job.plan` lang key and replaced the plan summary line.
  `LangKeysTest.everyKeyIsDefinedOnce` now guards against duplicate keys (A2).
- A rate-gated scroll could freeze the craftable strip's pending offset. It now expires
  (A2).
- The Buffer menu sent every action from TAKE upward to inventory handling, so new filter
  actions were ignored. The range is now bounded (B1).
- The Storage-mode upgrade path rebuilt settings without the new insert filter. It keeps
  the filter now (B2).

## Not verified here

- The physical Ctrl key in JEI and Shift-click range selection on the slot strip. Their
  logic is tested; the real key presses are not simulated.
- The no-screen chat path for job notices. Its code is unchanged and was not captured.
- Any human play (V1).
- Gated waves C, D, E and G. They wait on decisions PD1–PD6.
